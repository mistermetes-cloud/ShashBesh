# Данные для собственной нейросети

## Источник и контракт

`packages/training` превращает проверенный журнал в универсальные JSONL-записи `shashbesh-decision-v1`. Сначала выполняется полный replay с проверкой цепочки и правил. Затем состояния восстанавливаются последовательными переходами движка; сохранённые снимки никогда не принимаются как доказательство легальности.

Каждая строка содержит:

- `decisionId`, `gameId`, `eventSeq`, `rollId`, версию схемы и режим;
- `before`: поле, фишки, текущий игрок, фаза, бросок и оставшиеся номиналы до действия;
- `dice`: два выпавших значения;
- `legalActions`: все допустимые первые действия, продолжаемые до максимальной суммы;
- `selectedAction`, `decisionKind`: выбранный ход либо `pass` с `selectedAction:null` и пустым списком, когда хода нет;
- `after`: состояние после действия/вынужденного пропуска;
- `captures`: владельцы и состояния сбитых фишек до/после;
- `controller`: `human`, `agent` или явно `unknown`, анонимный идентификатор и версия агента;
- `result`: финальный победитель и метка `win`/`loss` с reward +1/−1 либо неизвестный результат с reward null;
- `provenance`: хеш исходного события, конечный хеш журнала, хеш геометрии, правила и RulePolicy.

Формальная схема: `packages/training/schema/decision.v1.schema.json`. Допустимость переходов проверяет движок, JSON Schema описывает структуру. Схема снимка допускает расширения полей состояния. Версии схемы, признаков и правил независимы.

Журнал записывает участника решения в момент каждого действия, включая ручной выбор при остановленном боте и вынужденный пропуск. Смена человека/бота не переписывает прошлые записи. Первое событие новой партии содержит состав участников. Идентификаторы людей локальные и анонимные; персональные данные не нужны. Старый журнал без авторства остаётся `unknown`, если не дан явный sidecar. Неизвестный автор не объявляется человеком или агентом по догадке.

## Четыре режима

1. `human-human`: все текущие участники — люди.
2. `human-ai`: люди и агенты.
3. `ai-ai`: агенты с разными id/версиями.
4. `self-play`: одна политика/версия играет за несколько сторон.

Режим вычисляется по составу и обновлениям участников в момент решения. Sidecar старого журнала может задавать `controllers` по P1..P4 и диагностическое `termination: timeout|error|unfinished`. Проверенный победитель всегда имеет приоритет. Незавершённым играм не назначается проигрыш; они не годятся для value target, но легальные действия могут использоваться для imitation learning.

## Экспорт

В UI: «Экспорт данных ИИ». Поддерживаются текущая партия и открытый replay. Это отдельный JSONL, исходный журнал сохраняется.

```bash
npm run dataset -- --input artifacts/first-game.jsonl --output artifacts/training/decisions.jsonl
# Для журнала без авторства:
npm run dataset -- --input legacy.jsonl --metadata participants.json --output decisions.jsonl
```

Пример sidecar:

```json
{"controllers":{"1":{"kind":"human","id":"anonymous-A","version":null},"2":{"kind":"agent","id":"my-network","version":"checkpoint-001"}},"termination":"unfinished"}
```

CLI создаёт исходный датасет, `.features.jsonl` и `.manifest.json` с геометрией CSV, версиями, числом записей и конечным хешем. JSONL переносим в Python/PyTorch/JAX; внешние API и конкретный ML-фреймворк не требуются.

## Признаки `shashbesh-features-v1`

- 20 фиксированных слотов P1-1..P4-5; отсутствующие игроки замаскированы.
- 73 числа на фишку: принадлежность активному игроку, 5 статусов (включая отсутствие), 65 позиций (64 клетки CSV + резерв), outerSteps/48 без обрезания, homeIndex/4 или −1.
- Маска игроков, one-hot активного игрока и двух кубиков, количества оставшихся номиналов 1..6.
- Переменная ось кандидатов: слот фишки, вид действия, номинал, индекс целевой клетки CSV, маска захвата из 20 слотов. Для pass — отдельный кандидат `[-1,3,0,-1,0...0]`.
- `chosenIndex`: цель pointer policy; `valueTarget`: +1/−1 или null. При batching дополнить кандидаты padding и attention mask. Выбранный индекс обязательно принадлежит списку допустимых кандидатов.

Номер партии, конечный результат и состояние после действия — метаданные/targets, не вход модели. Encoder использует только `before`, бросок и допустимые действия; не подмешивает будущие состояния. Порядок физических клеток и домашние связи входят в manifest из CSV. Геометрия с другим хешем отклоняется.

Начальная схема обучения: behavior cloning по `chosenIndex`, отдельная value head по известным исходам, затем self-play с новыми версиями политик. Базовые эвристические боты дают начальные данные, не гарантированно оптимальные метки. Для policy gradient впоследствии нужны явно записанные вероятности поведения и параметры политики; сейчас они не выдумываются.

`split(gameId)` распределяет целые партии 80/10/10 между train/validation/test. Все решения одной партии остаются в одной части. При объединении экспортов дедуплицировать `(gameId,decisionId)`; сохранять RulePolicy и версию агента. Для строгих оценок также разделять семейства seed и версии политик, исключая повторные воспроизведения одной партии.

Если одна партия экспортирована сначала незавершённой, затем завершённой, при объединении финальные метки из проверенного более полного журнала имеют приоритет над `unknown`. Префиксы исходных журналов должны совпадать; конфликтующие завершённые истории нельзя объединять молча.

Проверенный пример: `artifacts/training/self-play.jsonl`, 201 запись, каждая прошла JSON Schema; рядом `.features.jsonl` и `.manifest.json`. Это партия greedy против greedy, не обученная нейросеть.
