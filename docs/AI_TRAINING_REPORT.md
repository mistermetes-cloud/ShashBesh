# ShashBesh AI v0.1 — обучение и контрольные турниры

Реализована первая обучаемая нейросеть и агент `ai-v0.1`. RULES_V1.md и геометрия CSV не изменены. Модель доступна в UI вместе с Random, Greedy и Tactical. Это behavior cloning Tactical; self-play оптимизация весов не запускалась.

## Архитектура

- Компактная MLP: **269 → 24 tanh → 1**, 6505 обучаемых параметров.
- 226 чисел описывают публичное состояние, 43 — отдельное допустимое действие.
- Вход построен из уже существующего `shashbesh-features-v1`: 20 слотов фишек, статусы/координаты CSV/прогресс/дом, маска игроков, текущие кубики и оставшиеся значения. Для действия — тип, номинал, цель, захваты, прогресс выбранной фишки и публичные угрозы.
- Выход — **логит предпочтения**, не калиброванная вероятность победы и не точная Q-оценка.
- NumPy обучает, TypeScript выполняет inference в браузере/CLI. Матрицы хранятся в JSON. Независимый oracle проверяет согласованность вычислений с точностью 1e-5.
- `ActionScorer` отделяет архитектуру от агента; для новой архитектуры нужен новый loader/featureVersion, без изменения Engine.
- Каждый примитивный ход нейросети получает свежие публичные состояние и маску максимальных легальных префиксов. Выбирается только элемент этой маски; затем действие повторно проверяется движком. Пропуск возможен только при пустой маске.
- Checkpoint копируется при создании scorer и не меняется внутри партии. Seed, журнал, следующий бросок и результат партии не передаются модели.

## Данные и проверки

Проверены 19044 записи. Из них 14276 принадлежат Tactical; 4768 решений остальных авторов исключены из supervised fit. Использованы существующие JSONL (722 записи из трёх источников), включая проверку 201 ранее экспортированной строки и числовых признаков против исходного replay. Два старых журнала с Tactical аннотированы по сохранённым отчётам турниров. Дополнительно собраны 64 завершённые партии Tactical/self-play Tactical/смешанных составов для 2–4 игроков.

Проверка каждой записи: версия/RulePolicy/геометрия, инварианты before, совпадение текущего игрока и двух кубиков, точное совпадение допустимой маски с Engine, допустимость выбора, after через applyAction/finishRoll, сведения о захватах, завершённый результат. Новые записи получены из полностью проверенного журнала.

| Выборка | Партий с решениями Tactical | Решений |
|---|---:|---:|
| train | 55 | 11221 |
| validation | 2 | 411 |
| test | 9 | 2644 |

Разделение по gameId (`split` 80/10/10 по хешу), не по отдельным ходам; пересечения отвергаются как TS-подготовкой, так и Python-loader. Фактические доли не ровно 80/10/10 из-за небольшого числа партий и разной длины. В manifest есть также одна проверенная Greedy-партия без обучающих Tactical-строк; поэтому общее число source-games на единицу больше числа партий fit/evaluation.

Encoder явно использует только before и признаки легальных действий. Изменение after/финального результата не меняет X (проверено тестом). В X нет идентификаторов партий/seed, будущего броска, provenance/log head или терминальной награды. Результаты служат проверкой/targets для будущего RL, но не входом и не критерием отбора победивших Tactical-партий.

Для выставления из резерва ID одинаковых фишек взаимозаменяемы. Точный chosenIndex сохраняется; loss дополнительно принимает доказанно эквивалентные deployment-кандидаты (совпадают kind/value/from/to/path/captures, обе фишки в резерве). Иные действия не объявляются эквивалентными.

## Обучение

Adam, lr 0.002, batch 64, L2 1e-4, gradient clip ±5; 12 эпох, seed 20261009. Loss: −log суммы softmax-вероятностей выбранного/эквивалентных deployment-действий, padding маскируется. Checkpoint выбран только по validation loss: **эпоха 11**. Test оценён один раз после выбора, веса по результатам турниров не подбирались.

Оценка ресурсов до запуска: Pentium B970 2.30GHz, 2 ядра, 7843 МиБ RAM, доступно около 3777 МиБ, swap уже использовался (~1601 МиБ). NumPy 2.2.6, один BLAS-поток, GPU не использовался. Budget: до 12 эпох, 120 секунд и 512 МиБ RAM; текущий корпус укладывается в него. RAM guard проверяет наблюдаемый peak, это не жёсткий лимит ОС.

Время загрузки файлов и финальной оценки test не включено в таймер цикла оптимизации. Peak RSS относится ко всему Python-процессу.

Последняя колонка исключает вынужденные случаи, где любой кандидат входит в целевой эквивалентный набор. Общая accuracy завышает впечатление о качестве из-за вынужденных ходов/пропусков. Для невстречавшихся партий test содержит 2644 решения из 9 партий; содержательных выборов — 1483. Validation loss до fit 0.5826, после 0.4955; улучшение подражания не равно доказательству выигрыша над учителем.

## Контрольные турниры

144 партии: по 24 **парных** независимых от fit seed на соперника. В каждой паре одинаковый поток кубиков, неизменённый жребий, перестановка участников P1/P2. Для каждого соперника нейросеть по 24 раза находится на каждом физическом месте и по 24 раза начинает/ходит второй. Random/Greedy/Tactical сохраняют исходную реализацию; их поток случайного выбора независим от кубиков и одинаков внутри пары.

Контрольные seed `control-v01-{opponent}-{0..23}` отсутствуют в обучающей выборке. Сохраняются все журналы, результаты и state hash. Replay проверен для двух начальных партий каждого соперника.

| Соперник | Победы AI v0.1 | Победы соперника | Доля побед AI | 95% paired-bootstrap диапазон |
|---|---:|---:|---:|---:|
| random | 41/48 | 7/48 | 85.42% | 77.08–93.75% |
| greedy | 34/48 | 14/48 | 70.83% | 60.42–81.25% |
| tactical | 19/48 | 29/48 | 39.58% | 29.17–52.08% |

Все 144 завершились без тайм-аутов и ошибок. Интервалы получены 2000 bootstrap-перевыборками целых пар seed, не отдельных связанных партий. Это оценка неопределённости небольшой серии, не гарантия для других seed/составов. В этой серии модель выигрывала чаще Random и Greedy; **превосходство над Tactical не подтверждено** (19 побед против 29). Оптимальность стратегии не заявляется. Контролируемое качество в партиях на 3–4 игроков пока не оценивалось; законность inference для этих составов проверена тестами.

## Подготовка self-play и отката

`ai:selfplay` — ограниченный генератор exploratory self-play из frozen checkpoint (temperature 1), а не бесконечное обучение. Сохраняет исходный журнал, before/after/mask, compactCandidates, behavior probability/logProbability, model hash/версию и terminalReward +1/−1 для обеих сторон. Неизвестные outcomes имеют reward null и не должны идти в policy/value fit.

Пилот: 2 завершённые партии, 432 перехода, награды победителей и проигравших обе присутствуют. Время 19.62 с, наблюдаемый RSS 143.83 МиБ. Весы не обновлялись. Ограничения: 2 игры по умолчанию, бюджет 60 секунд/384 МиБ; validator не допускает >16 игр/>120 секунд без новой оценки ресурсов.

В Python подготовлен и проверен конечными разностями `selfplay_loss_grad`: on-policy REINFORCE с конечным результатом, положительные и отрицательные награды участвуют. Он не вызывается supervised main. Для многократных обновлений на старых траекториях нужны importance ratios/KL control или PPO, а для уменьшения дисперсии — baseline/value head; это ещё не реализовано.

`compareModels` играет candidate/champion на одинаковых парных seed и swapped seats, возвращает evidence. Promotion gate требует ≥24 уникальных пар, отсутствие незаконных действий/тайм-аутов, отсутствие heldout-регрессии >2 процентных пунктов и нижнюю Wilson-границу head-to-head >50%. Wilson здесь консервативный screening, не точный paired CI. Никакая новая версия сейчас не продвигалась на основании пилота.

`registry.json` хранит active/previous, версии, контрольные суммы, parent и dataset hash. При продвижении checkpoint архивируется под своим хешем отдельно от экспериментального файла. Проверка checksum и scorer выполняется перед активацией. Monitor откатывает при safety failure, явной heldout-регрессии или подтверждённом проигрыше предыдущей версии; неубедительный результат сам по себе не вызывает откат. Ручной rollback восстанавливает **точные прежние веса**, а не только название. Первая v0.1 пока не имеет previous. После смены active-model начать новые партии; для production bundle нужна пересборка.

## Артефакты и воспроизведение

- `packages/agents/models/shashbesh-v0.1.json`: сохранённая версия.
- `packages/agents/models/active-model.json`, `registry.json`: локальная активная версия и реестр.
- `artifacts/ai-v01/data/`: исходные журналы, проверенные JSONL/числовые признаки, compact.jsonl и manifest.
- `artifacts/ai-v01/training-config.json`, `training-metrics.json`, `inference-oracle.json`, `resource-assessment.json`.
- `artifacts/ai-v01/tournaments/`: summary/results и все 144 журнала.
- `artifacts/ai-v01/selfplay/`: две партии и обучающие transitions обеих сторон.

Model checksum: `35606b395852c14756e2d1828e31857fe24a652c2d64f5bbf717e6a495f1387e`.
Corpus checksum: `186b004c25b083abd31a848ac0a40d41292355031b6fbe41c93ca2ea7e1152f6`.

```bash
npm run dev
npm run ai:prepare -- --games 64 --output artifacts/ai-v01/data
npm run ai:train -- --data artifacts/ai-v01/data --output artifacts/ai-v02/candidate.json --model-version "ShashBesh AI v0.2" --epochs 12 --max-seconds 120
npm run ai:evaluate -- --pairs 24 --seed-prefix control-v01 --output artifacts/ai-v01/tournaments
npm run ai:selfplay -- --games 2
npm run test:neural-python
npm test
npm run build
```

Для обучения нужен Python/NumPy (`packages/neural/python/requirements.txt`); для игры Python не нужен. Повторный fit не активирует checkpoint автоматически и не перезаписывает существующий файл без явного --overwrite. Для новой версии использовать новые output/model-version и свежие контрольные seed, не подбирать её по уже просмотренным контрольным результатам.

## Ограничения и следующая версия

- Validation всего 2 партии; увеличить её до десятков независимых партий и стратифицировать составы/стартовые места на уровне gameId.
- Teacher выбирает полную последовательность броска, student — отдельные префиксы; добавить признаки лучших допустимых продолжений/поиск внутри текущего известного броска, не подглядывая следующие кубики.
- Абсолютные слоты/координаты: добавить проверенную симметрийную augmentation из CSV/actor-relative encoding с новым featureVersion.
- Больше независимых test/control seed и контрольные 3–4-player серии до утверждений о более сильной стратегии.
- Value head, нормализация advantage, replay/checkpoint-lineage и ограниченный self-play fine-tuning с champion gate; не запускать длительный цикл без новой оценки CPU/RAM.
- При увеличении корпуса использовать потоковые/minibatch загрузчики или mmap: текущий NumPy-loader держит небольшой корпус в памяти.
